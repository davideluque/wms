# Catalog identities and units for the retail pilot

A picker needs to know whether “2” means two shirts, two six-bag bundles or two kilograms. The proposed model resolves a source code to a particular variant and package, then records the conversion used on that transaction. Start with individual pieces and verified, fixed-count packs of one variant. A merchant can use internal item codes with or without supplier GTINs.

## Minimum data dictionary

These are proposed WMS constraints. A merchant is the owner of a catalog. A source namespace identifies one supplier catalog, POS installation, online shop or internal label series belonging to that merchant.

| Record | Minimum fields | Identity and constraints |
| --- | --- | --- |
| Product and variant | Merchant, product ID and display name, variant ID, internal SKU, option values, base unit, allowed quantity increment, active status | Use immutable IDs. Require a unique internal SKU per merchant, including retired SKUs. A variant without size/colour has its own ID. On a product with options, enforce one variant per normalized combination of option IDs and value IDs. Treat renaming “azul” as a display change. |
| Unit | Unit code, dimension, exact scale to a reference unit | Make each code unique within its code system. Use integer pieces for countable stock. For external messages, UNECE Recommendation 20 includes H87 for piece, KGM for kilogram and GRM for gram. Package type codes describe containers. Their contents require a separate, product-specific conversion. [UNECE code list recommendations](https://unece.org/code-list-recommendations) · [Count code](https://service.unece.org/trade/uncefact/publication/SupplyChainMGMT/SCRDM/HTML/043501.htm) · [Mass codes](https://service.unece.org/trade/uncefact/publication/Transport-Logistics/eCMR/HTML/04527.htm) |
| Package | Merchant, package ID, variant ID, description, base units per pack, whether intact packaging is required for the sale | One “each” package per variant has factor 1. Countable pack factors are positive integers. Two different retail presentations can have the same factor. Once used, give a changed pack its own ID. Keep the prior one available for identifying remaining physical stock. |
| External mapping | Merchant, source namespace, identifier type, original value, comparison value, package ID, validity start/end, revision ID and evidence | For a source-specific alias, require at most one resolution for `(merchant, namespace, type, comparison value)` at a given time. Distinct namespaces may both use `0042`. Preserve exact input and source-specific case rules. An overlapping claim stays unresolved. Prefer the source’s stable variant ID where it distinguishes products that share a SKU. |
| GTIN mapping | Merchant, validated GTIN in a 14-digit comparison form, original representation, package ID | Within one merchant catalog the same GTIN resolves to one trade-item presentation across all suppliers. Keep check digits and leading zeroes. Unit and case GTINs can point to separate packages of the same variant. Use the issuing brand owner’s identifiers. [GS1 GTIN formatting](https://support.gs1.org/support/solutions/articles/43000734386-are-all-gtins-unique-numbers-) · [GS1 allocation responsibility](https://support.gs1.org/support/solutions/articles/43000734414) |
| Posted line | Merchant, source/document/line reference, movement ID, variant, package, mapping revision, original quantity and unit, factor, resulting base quantity, time and location | Give each physical movement a stable, unique operation ID per merchant. A line can be fulfilled or returned in parts. Freeze the resolution and factor when posting. Retain a link to its prior movement for a correction or return. |

GS1 distinguishes size and colour combinations when assigning trade-item identifiers. A supplier’s style name can group shirts for browsing while the sale names one specific variant. The merchant’s code can differ from every supplier's number. For example, supplier A’s `0042` can mean navy M and supplier B’s `0042` navy L. A bare scan returning only `0042` on a mixed retail shelf needs another discriminator or an internal label. Selecting the first supplier in the list could send the wrong size. [GS1 guidance on size and colour](https://support.gs1.org/support/solutions/articles/43000734083-how-many-gs1-gtins-do-i-need-when-i-have-a-product-with-many-sizes-and-colours-)

## When a six-bag case becomes a five-bag case

Suppose two cases of six 3 kg ice bags were received under a supplier’s old case code. A later delivery has three cases of five. Keep both package IDs and record 12 + 15 = **27 bags**. A return of one intact case from the first receipt removes six, leaving 21. An old purchase order reprinted after the change must still show its six-bag presentation. GS1’s pack/case quantity rule requires a new GTIN at the changed grouping level. The unchanged individual bag keeps its identity. A change to the declared net content of the bag raises a separate trade-item decision. [GS1 GTIN Management Standard, declared net content and pack/case quantity](https://www.gs1.org/sites/default/files/docs/barcodes/GS1_GTIN_Management_Standard.pdf)

If the supplier reuses a private case code, end-date the old mapping and retain both revisions. A dated purchase line with a saved package establishes what was ordered. If both cases still sit on the shelf, use the printed quantity, distinct GTIN or verified local label to resolve a scan. Arrival date alone cannot identify a case from mixed stock. If a previously posted mapping was wrong, identify the affected movements, verify the original quantities and post linked corrections. Update unposted work after review.

Reprint a damaged internal barcode for the same verified item and package using its existing value. For a relabel, store the old and new identifier, package, actor, time and reason. Retire an ambiguous label for future use while retaining its lookup history. A label operation changes zero physical units. If the merchant promises a sealed case, track the intact packs or have staff verify one before promising it. Twenty-seven loose bags can fill 27 each-unit orders but do not establish that an intact five-bag case is available.

## Precision and products sold by weight

For countable goods, validate the entered quantity against the presentation’s increment and intact-pack rule before converting. Require a whole-number base result. An order for 1.5 shirts or half of an intact six-bag case needs review, even though half that case converts to three whole bags. Preserve the source line. A request for three loose bags can be supplied by opening a six-bag case if the merchant allows breaking packs. Record three bags remaining and the loss of one intact case. Do not maintain separate additive on-hand balances for both the original case and the same six bags.

A prepacked tray sold by the piece can be countable even when its label mentions weight. Loose produce sold by actual net weight needs measured quantities. If added later, define scale resolution and ledger precision, store the measured value and unit, and convert using exact decimal arithmetic. For example, 1.275 kg plus 0.725 kg equals 2,000 g. If a scale reads only to 10 g, a supplied value of 1.275 kg needs a source check. Preserve the observation and obtain an authorized correction. Keep price rounding in the sales system. A crate count, a selling price or a nominal average cannot reconstruct the weight of the actual pick. [GS1 variable-measure trade items](https://support.gs1.org/support/solutions/articles/43000734396-what-is-a-variable-measure-trade-item-) · [BIPM SI Brochure](https://www.bipm.org/en/si-brochure-9)

**Pilot test.** Receive both ice case sizes on the same day, reprint the old case label, return a case against its original receipt, and replay that return. Ask a picker to scan the conflicting shirt alias with and without supplier context. Pass when the unexplained scan remains actionable, the receipt and return quantities remain reproducible, the reprint moves no stock, and the final balance remains 21 bags after replay.
